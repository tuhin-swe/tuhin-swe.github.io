About

My path into QA wasn't the usual one. I spent a year at Shohoz Software supporting clients directly and coordinating fixes with developers, which taught me how a bug actually affects a user, not just how it reads in a test case. That's what pulled me into testing full-time.

End-to-end testing

A product is tested as one connected system: a customer orders, a seller accepts, a rider delivers, the admin sees it all. If any role breaks the chain, the release waits.

Bug reports that get fixed

Exact reproduction steps, root-cause analysis, severity and priority. Checkout-blocking and payment issues are flagged Critical so the team can triage fast. Every fix is retested before release.

API and beyond

REST API testing in Postman for status codes, payloads and business logic such as fees and commissions. On ReadyPOS I stepped into the codebase and shipped fixes and features myself.

Spotlight

ReadyPOS, where QA met development

After testing the system end to end and reporting every issue, I was given codebase access and took ownership of getting it customer-ready.

  • Fixed defects directly in a dedicated QA branch and verified each fix myself
  • Built new features by thinking like a shop owner: what a customer needs on day one, where they might get stuck, and what makes daily use effortless
  • Refined the UI across the product so it works as one cohesive, modern system
  • Used AI-assisted development tools to implement and verify changes faster
Outcome: a POS product shaped around real business needs, with QA and development working as a single loop.

How I work
